# Vooya FS

Vooya FS is a Rust-powered execution engine for **batch filesystem work in Node.js**.
It continues the former Rush-FS project under the Vooya name, with a narrower and
more honest promise: keep Node-compatible APIs where useful, and cross into Rust
only when a recursive or fused operation can amortize the native boundary.

> The `@vooya/fs` rename and the APIs on this development branch have not been
> published to npm.

## One boundary, one batch

```text
Node application
  ├─ tiny / one-off filesystem call ─────────────── node:fs
  └─ recursive or combined workload
                    │ one Node-API call
                    ▼
             Rust traversal engine
                    │ walk · filter · metadata · I/O
                    ▼
               one batched result
```

That means Vooya FS is a good candidate for repository indexing, build-tool input
discovery, cache cleanup, package scanning, and large recursive copy/removal. It is
usually not the right tool for an isolated `existsSync` or a tiny directory.

## Start with a fused scan

```ts
import { scan } from '@vooya/fs'

const sources = await scan('./packages', {
  include: ['**/*.{ts,tsx,rs}'],
  exclude: ['**/node_modules/**', '**/dist/**'],
  skipHidden: true,
  concurrency: 4,
})
```

`scan` walks, filters, and collects metadata inside one native task. It is a Vooya
FS extension; compatibility-oriented operations such as `readdir`, `glob`, `cp`,
and `rm` remain available separately.

On the local Apple M4 Pro / Node 22.22 development fixture, `scan` processed 2,728
files and 341 directories in about **10.7 ms**, versus **34.0 ms** for recursive
Node `readdir` plus per-entry `lstat`. On the 8-file fixture Node was faster. Read
[Benchmarks](/benchmarks) for the method and scale boundary.
