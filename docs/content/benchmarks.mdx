# Benchmarks

Benchmarks in this repository are evidence for choosing an execution boundary, not
release assertions. Each performance suite records fixture scale, runtime and
platform, warmups, measured samples, wall-clock aggregation, and RSS deltas.

## Reproduce

```bash
corepack pnpm build
corepack pnpm perf:fs scan --iterations 10 --warmup 2 --json .perf/scan.json
corepack pnpm perf:fs readdir --iterations 10 --warmup 2 --json .perf/readdir.json
corepack pnpm perf:fs glob --iterations 10 --warmup 2 --json .perf/glob.json
```

The default matrix stops at `medium`. Add `--large` for the 156,248-file fixture
or `--extreme` for the manual-only stress fixture; these modes can consume
substantial time and disk space.

Use the same machine and quiet background conditions when comparing changes. Do
not compare ratios from different hosts as if they were the same experiment.

## Current scan boundary

Apple M4 Pro, Node 22.22, 2 warmups and 10 measured samples:

| Scale  |                Fixture | Node recursive readdir + lstat | Vooya FS `scan` |                Result |
| ------ | ---------------------: | -----------------------------: | --------------: | --------------------: |
| tiny   |       8 files / 2 dirs |                        0.26 ms |         3.43 ms |    Node 13.44x faster |
| small  |    104 files / 13 dirs |                        1.43 ms |         3.51 ms |     Node 2.45x faster |
| medium | 2,728 files / 341 dirs |                       33.98 ms |        10.70 ms | Vooya FS 3.18x faster |

The useful conclusion is the crossover, not the largest ratio: native task setup
dominates tiny trees, while fused traversal and metadata collection pays off as
the tree grows.

## Reading reports

- Compare absolute time as well as ratios.
- Treat negative RSS deltas as sampling and garbage-collection noise, not freed
  memory attributable to one implementation.
- Rerun outliers and inspect raw samples.
- Validate behavior with conformance tests separately; a fast mismatch is a bug.
- Tune concurrency per representative storage and tree shape.

Generated per-API tables live on API pages when a checked-in report is available.
